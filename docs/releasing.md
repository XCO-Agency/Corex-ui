# Releasing @xco-agency/corex-ui

`@xco-agency/corex-ui` is published to the public npm registry from this pnpm monorepo. The workspace root is private. `playground` is private and ignored by Changesets. Nothing is published to Packagist or GitHub Packages.

Day-to-day steps for contributors and maintainers are in [CONTRIBUTING.md](../CONTRIBUTING.md). This page is the automation contract.

## Version and tags

| Source                                     | Role                                                                                                                                            |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/corex-ui/package.json` `version` | Version npm publishes. Changesets bumps it.                                                                                                     |
| Root `package.json` `version`              | Kept identical by `node scripts/sync-root-version.mjs` during Version Packages.                                                                 |
| `packages/corex-ui/src/version.ts`         | Generated by [`scripts/sync-version.mjs`](../packages/corex-ui/scripts/sync-version.mjs). Do not edit it by hand and do not remove that script. |
| Git tag                                    | Annotated tag `vX.Y.Z`, exactly `v` plus the package.json version. Not `@xco-agency/corex-ui@X.Y.Z`.                                            |
| GitHub Release                             | Created for that tag. Notes come from the matching section of `packages/corex-ui/CHANGELOG.md`.                                                 |
| npm dist-tag                               | `latest` for a stable version. A prerelease such as `2.4.0-beta.1` is tagged `beta` and marked as a GitHub prerelease.                          |

Before any real `npm publish`, the publish workflow runs `scripts/assert-release-version.mjs --require-tag`. The tag must be an annotated `v` tag, and both package.json versions must equal the tag with the leading `v` removed.

## What does not get a tag

- A push to `main` that does not change the library version. Merging this automation is one of those pushes: the repo stays on 2.3.2, so nothing is tagged or published.
- A version npm already has. Tags `0.0.1` and `0.0.2` stay as they are. The rest of the old history is not backfilled.
- The Changesets action's default monorepo tag (`@scope/name@version`). Release turns that off and creates `vX.Y.Z` itself.

npm `latest` was **2.3.1** when this was added. The repository version **2.3.2** is not on npm. The next Changeset release publishes the next version (the 2.3.2 code rides along inside it) unless a maintainer publishes 2.3.2 first. To publish 2.3.2 without a new changeset, check out the commit whose `package.json` version is 2.3.2, push an annotated tag `v2.3.2` on that commit, and publish the GitHub Release. Publish Package then asserts the tag and uploads. Do not invent tags for versions that are already on npm.

## Workflows

### CI (`.github/workflows/ci.yml`)

On every pull request and every push to `main`: `pnpm install --frozen-lockfile`, version sync check, `pnpm typecheck`, `pnpm test`, `pnpm build`. Pull requests that change releasable library files must include a changeset. The Version Packages pull request is skipped for that check because it consumes the changeset files.

### Release (`.github/workflows/release.yml`)

On every push to `main`, `changesets/action@v2.1.2`:

- Pending changesets: open or update the **Version Packages** pull request (`pnpm version-packages`).
- No changesets: run `pnpm release`.

`pnpm version-packages` is `changeset version`, then the root version sync, then `pnpm --filter @xco-agency/corex-ui run sync:version`.

`pnpm release` (`scripts/release.mjs`) reads the parent commit's library version.

- Same version: exit without tagging. This is the normal result for docs, playground, and tooling merges.
- Version changed, already on npm: exit without tagging.
- Version changed, not on npm: create the annotated tag, push it, create the GitHub Release, and write `release-tag.txt`.

The following job calls Publish Package with that tag. A release created by the default `GITHUB_TOKEN` does not start other workflows, so the npm publish cannot depend on the `release: published` event alone.

### Publish Package (`.github/workflows/publish.yml`)

Triggers:

- `release` type **`published` only** (not `created`)
- `workflow_dispatch` with `dry_run` (default **true**)
- `workflow_call` from Release after a new tag

A real publish checks the tag, skips the upload if npm already has that version, then typechecks, tests, builds, and runs `npm publish --access public --provenance` from `packages/corex-ui`. Authentication is npm Trusted Publishing (GitHub OIDC), not an npm token. The job uses Node 24 and npm 11.5.1 or newer. Prerelease versions get their prerelease identifier as the dist-tag instead of `latest` (`npm publish --tag`).

npm records the workflow that started the publish. `release: published` and `workflow_dispatch` run `publish.yml`, so that filename is the trusted publisher. Release on `main` calls the same workflow with `workflow_call`, and npm then records `release.yml` instead. Both filenames need a trusted publisher on the package, and both workflows grant `id-token: write`. No GitHub environment is set.

A dry run from a branch such as `main` only checks that the two package.json versions match, then packs with `npm publish --dry-run`. It does not require a tag and it does not upload. A dry run checked out on a `v*` tag still requires that tag to match `package.json`.

`workflow_dispatch` with `dry_run` set to false publishes only when the selected ref is an annotated `v*` tag that matches `package.json`. Running it from `main` fails the tag check.

## Secrets

| Secret         | Used for                                                                                                                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GITHUB_TOKEN` | Provided by Actions. Opens the Version Packages pull request, pushes the annotated tag, and creates the GitHub Release. Do not put a second copy in the Release job's environment; `changesets/action` rejects a mismatch. |

Publish does not use `NPM_TOKEN` or `NODE_AUTH_TOKEN`. The library and its dependencies are on the public registry, so install does not need a read token. Provenance is generated from the job's `id-token: write` permission. The repository has to be public for npm provenance.

Trusted publisher configuration lives on npmjs.com for `@xco-agency/corex-ui` (GitHub Actions, organization `XCO-Agency`, repository `Corex-ui`). Add one publisher for workflow filename `publish.yml` and one for `release.yml`. Allow `npm publish` and dist-tag changes. Leave the environment empty. A new trusted publisher must publish successfully within two days of being saved.

## When a publish fails

The tag and GitHub Release can exist before npm has the version. Later pushes to `main` will not try again, because the version no longer differs from the parent commit.

Re-run the failed **Publish to npm** job, or run **Publish Package** on that tag with `dry_run` false. Re-running **Release** on the version-bump commit is also safe: the script reuses an annotated tag that already points at that commit and does not publish if npm already has the version.

Do not delete a tag that npm has already published under. npm versions cannot be replaced.
